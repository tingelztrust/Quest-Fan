# Quest 3 面罩风扇 / Quest Fan

ESP32-C3 SuperMini + LR7843 + 两只 5V 4010 离心风扇。板子提供局域网网页和 HTTP 接口；Quest 3 上的 2D Android 应用通过 Wi-Fi 直连板子，不要求电脑一直开机或持续连接 USB。

**当前功能：80% / 90% / 100% / 关闭。** 暂无「戴上头显自动启动」；以后可以研究，但须先在 Quest 运行其他游戏时验证后台佩戴状态是否可靠，**本版不能宣称已支持自启**。

## 现在就打开控制网页（电脑/手机）

1. 给 ESP32-C3 **供电**（当前调试可用 USB；独立使用时电池稳压 5V 须接到板子的 5V/GND）。板子上电会自动运行已烧录固件、连接预先配置的 **2.4 GHz Wi-Fi**，并在 **80 端口**启动网页服务器；电脑端**不用执行启动命令、无需挂载或常驻脚本**。
2. 电脑/手机连到能访问该板子的同一局域网，在浏览器地址栏**直接输入 [`http://192.168.10.178/`](http://192.168.10.178/)**（这是**当前这块板子**的 IP，我刚实测页面 HTTP 200；换路由器后可能变）。页面出现「低 80% / 中 90% / 高 100% / 关」，点按钮即可。电脑支持 mDNS 时也可试 `http://questfan.local/`。
3. 若网页打不开：先试 `http://<板子新IP>/state`，路由器 DHCP 客户端列表中找主机名 `questfan`；检查板子是否仍有电、2.4 GHz Wi-Fi 是否连上，以及访客网/AP 隔离。仓库里的 `web/index.html` 只是**供审阅的页面源码**，双击 `file://` 不会连到板子的 `/state` 接口。

其他人拿到新的 ESP32 时，需先按下方「第一次配置」章节填写自己的 Wi-Fi 并**烧录**固件；仅仅下载这个仓库或给空白板子供电不会自动出现网页。

> [!WARNING]
> 这是个人 DIY 接线说明，不是已通过安全认证的成品。先断开电池再接线、焊接或烧录；实物模块的端子排序和 XH2.54 插头极性可能不同，**必须看实物丝印并用万用表量电压、极性与短路**，不能仅按线色或照片插接。电池必须提供稳定 **5V 输出**，不可把裸锂电芯电压当作 5V。确认两风扇启动电流加板子电流不超过电池组、导线和接口额定值（此电池组标称最大 2A）。不清楚板子 5V 与 USB VBUS 的隔离情况时，烧录期间先拔下电池，不要盲目同时接电池和电脑 USB。

## 物料清单

- 主控：**ESP32-C3 SuperMini** ×1，已预焊排针。仅支持 2.4 GHz Wi-Fi 与 BLE。
- 风扇：**5V 4010 双滚珠离心涡轮、标称 9000 RPM、两线制** ×2。两只风扇同步调速，不能分别控制。
- 驱动：**LR7843 MOSFET PWM 开关模块** ×1；此接法使用低侧开关控制两只风扇的负极。电机电流**不经过 ESP32 GPIO**。
- 电源：独立 **5V 输出锂电池组**，XH2.54 接口，标称最大 2A。使用前测量实际输出与极性。
- 接线辅件：XH2.54 母对母一分二 ×1、XH2.54 母对母 ×1、XH2.54 转杜邦线、杜邦母母线（其中一根按实际需要剪成母对裸线）、XH2.54 母转裸线端子。另需合适的绝缘与固定材料；若模块通孔未装端子，需焊接工具。

## 接线图和实物照片

![电池、ESP32-C3、LR7843 和两风扇的连接示意](hardware/wiring.svg)

图中**红＝+5V、深色＝公共 GND、绿＝GPIO4→PWM、橙＝两风扇负极→LOAD**。线路交叉但没有实心连接点时**不连接**。这是**电气拓扑**，不是模块实物引脚排列图。MOSFET 各型号丝印可能不同；请先确认手上的模块确实有「电源 + / 电源 − / LOAD」和「PWM / 控制 GND」对应端子。若丝印不同，**先停下核对模块资料，不要硬套本图**。

```text
5V 电池组（输出 +5V / GND）
          │
      XH2.54 分线
          ├──────── ESP32-C3：5V、GND
          └──────── LR7843：电源 +、电源 −

电池 +5V ───┬── ESP32 5V
             ├── MOSFET 电源 +
             ├── 风扇 1 红线 (+)
             └── 风扇 2 红线 (+)

电池 GND ───┬── ESP32 GND
             └── MOSFET 电源 −

风扇 1 黑线 (−) ─┐
                  ├── MOSFET LOAD
风扇 2 黑线 (−) ─┘

ESP32 GPIO4 ─────── MOSFET 控制排针 PWM
ESP32 GND ───────── MOSFET 控制排针 GND
```

用户提供的局部接线关系（与上图相同）：

```text
电池 +5V ─────────────┬──── 风扇1 红线
                      ├──── 风扇2 红线
                      └──── MOSFET +
风扇1 黑线 ────────────┐
                      ├──── MOSFET LOAD
风扇2 黑线 ────────────┘
电池 GND ────────────────── MOSFET −
黑色两针控制排针：PWM ← ESP32 GPIO4；GND ← ESP32 GND
```

> 上一段是功率端的局部示意；**电池正负极也必须分别接到 ESP32 5V/GND**，否则拔掉板子 USB 后芯片断电、网页就无法控制。风扇红线不要接到 GPIO4。两只风扇负极接 LOAD，而不是直接接电池负极。

### 从零接线顺序

1. **断开电池和 USB。** 对照电池与 XH2.54 实物，用万用表确认正负、开路输出约 5V；不要仅看红黑线。确认风扇铭牌电压、模块输入范围、两风扇启动电流是否符合 2A 电源规格。尚未验证之前不让裸线相碰。
2. 如果 LR7843 模块未焊接：先焊牢**蓝色三位螺丝端子的 3 个通孔焊点**、**黑色两针控制排针的 2 个通孔焊点**，检查桥连、虚焊。ESP32-C3 已预焊排针，不要重复焊。
3. XH2.54 一分二把电池 5V / GND 分给 ESP32 与 MOSFET 功率输入；需要的母对母、转杜邦、母对裸线、母转裸线端子只用于适配接口。裸线入蓝色螺丝端子后轻拉确认夹紧，不留外露铜丝。**先测通断，确认 +5V 没有和 GND 短路。**
4. 两只风扇**红线**并在 +5V；两只**黑线**并在 MOSFET `LOAD`。若模块实物不是这一组接法所需的低侧开关端子定义，应根据模块资料改接，不要照搬。
5. MOSFET 黑色两针控制排针：`PWM` → ESP32 `GPIO4`；控制 `GND` → ESP32 `GND`。控制地和功率地必须共地。ESP32 的 5V 和 GND 还须确实接到电池输出，不能只给 MOSFET 供电。
6. 全部接完再复测短路、极性及螺丝端子；先固定和绝缘，防止佩戴中扯断、金属件短接或线束扫到风扇叶轮。**首次上电有异味、发烫或电池保护动作立即断电。**

## 第一次配置：让板子连 Wi-Fi

1. 在电脑安装 Arduino IDE 与 Espressif 的 Arduino-ESP32 板包（本项目已用 **3.3.12** 编译验证）。本仓库包含源码但不包含工具链。把 [`secrets.example.h`](firmware/quest-fan/secrets.example.h) **复制**为同一目录下的 `secrets.h`；填写你自己的 `WIFI_SSID`、`WIFI_PASS`。真实 `secrets.h` 已被 `.gitignore` 排除，**不要强行提交、贴截图或把密码写进 APK**。
2. 网络须提供 **2.4 GHz Wi-Fi**（ESP32-C3 不支持 5 GHz），优先 WPA2 或 WPA2/WPA3 混合；只有 WPA3、访客网客户端隔离、AP 隔离会导致连接或头显访问失败。Quest 可以用同一路由器的其他频段，只要头显和板子在可互访的同一局域网。
3. Arduino IDE 打开 `firmware/quest-fan/quest-fan.ino`，板型**手选 ESP32C3 Dev Module**（FQBN `esp32:esp32:esp32c3`），不是自动识别时可能出现的 **Ozobot DRVKit**。保持 **USB CDC On Boot = Disabled / default**；草图不依赖 USB 串口。连接 ESP32 的 USB 数据线后选实际串口（Linux 上通常 `/dev/ttyACM0`）。断开电池再烧录以避免未知的 USB/VBUS 反灌风险。
4. 先点**验证/编译**。确认无报错后才点**上传**；烧录会覆盖板子当前程序，非必要勿反复烧。上传日志应看到写入应用以及 `Hash of data verified`，只有「程序占用多少字节」并不算已上传。烧完拔掉电脑 USB，再接回已核对极性的 5V 电池供电。
5. 在路由器的 DHCP 客户端列表查找 `questfan`（板子主机名）对应的 **IPv4**。本机曾分到 `192.168.10.178`，**那只是示例，不是所有网络的地址**。从同一局域网的手机/电脑访问 `http://<板子IP>/state`，应返回类似 `{"on":false,"speed":80,"ip":"<板子IP>"}`。关机时 `speed` 仍是**记住的预设挡位**，不一定是 80。浏览器也可打开 `http://<板子IP>/` 用板子自带的四按钮页面。

> [!NOTE]
> 固件在上电时从闪存恢复**上次开关和挡位**。若上次状态为「开」，重新上电可能自动转；首次调试先保持安全距离并使用已验证的电池供电。板子网页无认证，只应放在可信局域网；**不要端口映射到互联网**。

## 电脑/手机：打开风扇控制网页

ESP32 自己在局域网内提供这个网页，不是安装在电脑上的常驻服务。电脑连入能访问板子的网络后，直接在浏览器打开 `http://<板子IPv4>/`，例如本机当前 `http://192.168.10.178/`（仅是这台板子本次 DHCP 地址）。网页四按钮对应 80% / 90% / 100% / 关；状态来自 `/state`。也可以尝试 `http://questfan.local/`，但 `.local` 取决于电脑的 mDNS 支持，Quest 端建议填 IPv4。

[`web/index.html`](web/index.html) 是固件 `quest-fan.ino` 的 `PAGE` 内嵌 HTML 的**同步副本**，用于审阅和修改。直接在电脑上双击本地 `file://.../web/index.html` **不能代替板子的服务器**：页面里使用 `/state` 等相对接口。要更新线上网页，应修改固件内嵌 `PAGE` 并重新编译烧录（或把同一版网页同步回固件）；本次包中两份内容已校验一致。电脑网页和 Quest APK 操作的是**同一块板子、同一组状态**，无需电脑端挂载、后台守护进程或 USB 常驻。

## Quest 3：安装 APK 并控制风扇

1. 头显开启开发者模式，用 USB 数据线连电脑；戴上头显同意「允许 USB 调试」。电脑运行 `adb devices`，状态必须是 `device`，不能是 `unauthorized`。
2. 在仓库根目录运行 `adb install -r android/dist/QuestFan-1.0.apk`。这是侧载 APK，可能在 Quest 应用库的「未知来源」里，显示名称为**面罩风扇**。安装时用 USB；安装后电脑和 USB 不再参与控制。
3. 头显接入能访问板子的 Wi-Fi/LAN。在应用顶部填入步骤 5 查到的**板子 IPv4**，点「连接」，确认显示从板子读取到的状态，再点 80%、90%、100% 或「关闭风扇」。APP 保存上次输入的 IP；IP 变了可直接修改。Quest 上 `.local` 解析不一定可靠，优先填 IPv4。若 DHCP 经常变，推荐在路由器上**为板子网卡做 DHCP 地址保留**，而不是把代码里的示例 IP 当成固定地址。
4. 若显示连接失败：先在同一网络的设备访问 `http://<板子IP>/state`；再排查板子是否靠电池给 ESP32 5V 供电、头显 Wi-Fi、IP 地址、AP 隔离及 WPA 模式。能读状态但风扇不转时，优先量 MOSFET 功率端 5V、公共地、风扇线，不要把网络成功等同于电机供电成功。

APK 源码在 [`android/`](android/)；本机可用 `bash android/scripts/build.sh` 从源码编译和运行协议测试。需 **Java 17、Android SDK Platform 34、Build-Tools 35.0.0**；脚本按测试结果继续编译、对齐、签名。公开 APK 是**本机 debug keystore 签名**的侧载构建，不含私钥；他人用自己的密钥重建后通常不能直接覆盖安装这份 APK，必要时先卸载旧应用（本地保存的 IP 会清除）。未来正式发布应使用自己妥善保管的发布签名，不应把密钥提交仓库。

上传前可运行 `python scripts/check_release.py`：检查照片与文档链接、网页与固件逐字一致、没有 `secrets.h` 或构建缓存。实际私钥和 Wi-Fi 凭据请只留在自己电脑，不要把它们手动强制加入 Git。

## 协议和维护边界

- `GET /state`：读取 `{on, speed, ip}`。
- `GET /gear?v=80`、`90`、`100`：选挡并开启；`GET /off`：关闭。PWM 在 GPIO4，1000 Hz、8 位；两只风扇共享控制。所有请求仅限同一可信局域网。
- 固件目前**没有** `/worn`、`/removed`、`/auto`；电脑轮询脚本并未随包发布。戴上自启属于以后待实机验证的更新，**本次不实现**。
